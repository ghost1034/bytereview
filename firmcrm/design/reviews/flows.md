# FirmCRM — end-to-end flow QA (functional + UX)

**Build:** dev, UI `http://localhost:5186`, API `http://localhost:8010` (v0.3.0, migrations at head).
**Date:** 2026-08-23. **Reviewer:** QA (senior, UX background).
**Method:** every flow driven in a real Chromium browser (headless Playwright 1.62, 1440×900, one isolated context per role),
with console + network capture on every page, cross-checked against the API with direct HTTP calls.
The shared chrome-devtools MCP was unresponsive for the whole session (`new_page` / `list_pages` returned nothing for the full
30-minute idle timeout), so a separate browser instance was used. No other agent's browser tab was touched.

Rules referenced: `docs/SECURITY.md` (RBAC matrix, ethical walls, business gates) and `README.md`.

**Counts — 2 P0, 9 P1, 13 P2 (24 findings).**

## What works well (verified, no defects)

- **Lead → convert.** Required-field validation, duplicate-account warning ("1 existing account matches 'Northwind Robotics'"), attach-to-existing (Convert stays disabled until an account is picked), new-account path, landing on the new opportunity, converted leads becoming read-only with a "View" action.
- **Unqualify requires a reason** — reason dialog with the confirm disabled while empty, inline "Reason is required." on blur, and the API refuses `status=unqualified` without a reason (400 `unqualified_reason`).
- **Closed Won gate.** Blocked with a precise explanation at every entry point: the header button is disabled with `title="Conflict check required"` → then `"Engagement letter must be signed"`; the stage rail shows a lock and the same text; and a **board drag onto "Drop to mark Won" is refused with a clear toast** — *"Conflict check must be cleared or waived before this opportunity can be marked won (current: none run)."* (`shots/flows-16-drag-won-blocked.png`, `shots/flows-02-opp-blocked.png`). Dragging onto "Drop to mark Lost" opens the reason drawer instead of closing silently.
- **Conflict search quality.** Running a check on an opportunity with adverse party "Northwind Robotics" correctly matched the existing client and routed to pending; the prospect's own account is filtered out of its own check (no false self-match).
- **Waiver control.** Manager's Decision list omits "Waived"; the API refuses `waived` from a manager (403 "Only a partner or admin can waive"), refuses a waiver with no note, and refuses "Clear" on a check with matches unless a note explains each match.
- **Closed Won side effects (first win).** Engagement created, account flipped to `client` with `client_since`, badge and Engagements row correct.
- **Ethical walls.** Once raised, the account 404s for non-members with good copy ("It may have been removed, or access is restricted by an ethical wall"), and disappears from the accounts list, contacts list, board, ⌘K search ("No matches") and the manager's CSV export (25 rows instead of 26). **Conflict search still matches the walled party but redacts it** — "Restricted matter (ethical wall) — contact Risk / General Counsel" (`shots/flows-11-wall-staff-404.png`, `shots/flows-12-wall-conflict-redacted.png`). Adding a member restores access immediately; a member who is not a partner gets no Lift button and is refused by the API (403). Every wall action is in the audit log (`wall.create`, `wall.add_member`, `wall.remove_member`, `wall.lift`).
- **Archive / restore.** Account with open opportunities is refused ("Account has open opportunities; close or archive them first"); archived accounts stay searchable in conflict checks with an "archived" marker; Show-archived toggles work on Accounts/Contacts/Campaigns; open opportunities cannot be archived until closed.
- **Duplicate contact email** — blocked with a specific message naming the existing record, and the form stays open with its values.
- **Import/export.** CSV downloads with correct filenames and headers; the template matches the accepted columns; a missing required column is rejected outright; bad rows produce a precise per-row exception table and a downloadable exceptions CSV; committing writes exactly the clean rows; **re-importing the same file updates rather than duplicating** (idempotent).
- **Auth.** Password policy (length, letters+digits, email local-part, common passwords) enforced inline and server-side; **lockout after exactly 5 failures** with the right message ("Account temporarily locked due to repeated failed logins.") and the correct password refused while locked; silent refresh works when only the access token is dropped.
- **Admin.** Weak password rejected inline; duplicate email → "Email already exists" with the dialog kept open; email not editable on an existing user; role edits round-trip; deleting an in-use stage is refused ("Stage has opportunities; move them first"); audit-log entity filter and pagination work (371 entries, 100/page).
- **RBAC in the UI matched the API everywhere except finding #8.** staff/marketing see no Data or Admin nav, no export buttons, no archive actions, no clearance Review button — and the API returns 403 for each. Manager/partner see Data + Admin; admin-only controls (Add user / Add practice area / Add stage / Save / Delete) are hidden from managers, and the API refuses them.

## Console and network

No JavaScript errors, no unhandled rejections, and no failed requests on any page, for **all five roles across 20 routes each**
(dashboard, tasks, leads, opportunities, clearance, engagements, accounts, contacts, campaigns, reports, settings, data, admin,
three record detail pages, three non-existent ids, one bad route).

- The only console noise is two **React Router v7 future-flag warnings** per page load (`v7_startTransition`, `v7_relativeSplatPath`) — cosmetic; silence them with the future flags in `frontend/src/App.tsx`.
- The only 4xx responses are the intentional ones: `404` for non-existent record ids (correctly rendered as a not-found card) and `403`/`400` for the RBAC and business-rule probes above.
- `/opportunities/{missing}` fires three parallel 404s (`/opportunities/{id}`, `/history`, `/walls/for/opportunity/{id}`). Harmless, but the detail page could skip the dependent queries once the main record 404s.

## Release readiness

**Not ready to ship.** The product is in good shape overall — the professional-responsibility machinery that distinguishes this
CRM (conflict/independence gates, waiver authority, ethical walls, audit trail) is well built and, with the exceptions below,
correctly enforced server-side; RBAC is consistent between UI and API; error copy is unusually good.

Blocking:

1. **#1 / #2 — the won→reopen→win/lose path corrupts Engagement data** (duplicate active engagements; live engagements on lost
   deals; accounts permanently flipped to client). This silently overstates annual engagement value and client counts, and pushes
   duplicate matters to the PSA. There is no UI to correct it. Fix before any pilot that reports on engagement value.
2. **#3 — a wrong current password signs the user out.** It is the first thing every admin-created user hits, and it looks like
   the app broke.
3. **#4 — a partner can lock themselves out of a wall they raised**, with no UI path to lift it. On a professional-responsibility
   control, an unrecoverable state needs an escape hatch.

After those, the clearance-authority gaps (#6, #7) should land before the app is used for real conflict decisions: both let a
manager make or overturn a determination that the documentation and the UI itself reserve for a partner. #5, #8, #9, #10 and #11
are ordinary pre-GA bugs. The P2 list is safe to schedule after launch, except #12 (import copy) and #13 (lead filter copy),
which are cheap and actively mislead.
